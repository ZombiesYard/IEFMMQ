\chapter{引言}\label{ch:introduction}

本文描述了所提出系统的设计、实现与技术评估。该系统是一个基于遥测证据的教学运行时，结合了程序包驱动的状态跟踪、检索增强的语言模型辅助生成以及微调视觉语言模型（VLM）的视觉事实提取功能，以支持高保真飞行仿真器中的程序性学习。本研究的动机源于教授复杂、序列敏感程序的挑战——以 DCS World 中 F/A-18C 冷启动任务为代表——以及将遥测证据、检索增强知识和视觉感知整合到一个统一的、受证据约束的教学运行时中的机遇。本章定义研究问题，追溯从研究计划到当前实现的演进过程，列举本研究的贡献，并概述论文剩余部分的组织结构。

\section{研究动机}\label{sec:intro-motivation}

程序性学习——获取必须在正确上下文中正确执行的固定有序动作序列——面临着将其区别于陈述性学习或概念性学习的独特挑战。学习者不仅需要记忆步骤，还必须识别每个步骤的适用时机，验证其前提条件是否满足，在推进前确认其完成，并在出错时恢复，而不将错误传播到程序的后续部分。在高保真仿真环境中，这些挑战因座舱或工作空间的复杂性、仪表信息的密度以及在执行不熟悉序列时保持态势感知的认知负荷而进一步加剧。

传统的培训辅助手段——视频演示、纸质检查单、教员引导示范——在初始熟悉阶段有效，但会打断仿真器内练习的连续性。暂停练习查阅手册或重播视频片段的学习者必须从座舱环境中切换注意力，从而丧失沉浸感，在某些情况下甚至会丢失最初触发查阅需求的瞬态仿真器状态。相反，来自大语言模型（LLM）的缺乏状态基础的纯文本辅助可能提供流畅但事实性错误的指导，因为模型无法获取当前仿真器状态。在这两个极端之间，需要一种\emph{有状态基础的、上下文感知的}教学方式：一个通过实时仿真器遥测数据观察学习者操作、检索相关文档、在遥测数据不足时从座舱中提取视觉证据、并在不中断训练流程的前提下提供简洁、可验证指导的系统。

DCS World 中 F/A-18C 的冷启动程序是本论文的训练场景。该程序包含 25 个步骤（S01--S25），分为六个阶段（P1--P6），从电瓶供电开始，历经发动机启动、航电配置、飞行控制检查，直至滑行准备（详见\S\ref{sec:bg-coldstart}）。每个步骤都带有显式的前提条件，这些条件取决于先前步骤的完成情况以及特定遥测条件的满足程度：例如，左发起动（S10）要求右发参数——转速、温度、燃油流量、尾喷口位置和滑油压力——在启动左发之前处于标称范围内。这些步骤间依赖关系使得冷启动任务成为航空、海事操作、工业维护和医疗程序指导中基于仿真器培训的序列敏感、状态依赖型程序性任务这一更广泛类别的代表性实例。TODO:CITE —— 智能教学系统和程序性学习文献。

本研究的核心前提是：通过将每个可操作的输出都建立于显式证据之上——遥测变量、门控规则评估、检索到的文档片段或视觉事实观察——可以使教学系统显著提升可靠性与可审计性。这种证据溯源约束既是架构层面的承诺，也是一项安全要求：在座舱程序的语境中，被错误高亮的控件或被错误识别的程序状态可能会使学习者产生混淆或误导。本文所描述的系统在一个包含自动化测试、基准测试工件和回放基础设施的可运行运行时环境中实例化了这一原则。

\section{论文愿景与范围}\label{sec:intro-vision}

本论文的研究愿景，如研究计划所述，核心是在 Meta Quest~3 上结合 DCS-VR~\citep{ThesisProposal1128} 构建一个以虚拟现实为先导的基于状态证据的教学系统。计划的系统将通过 VR 座舱内的眼动追踪、手部追踪和语音输入接收学习者交互；检索相关手册和检查单摘录；通过检索增强的 LLM 生成简洁、附带引文依据的步骤指导；并将指导渲染为头显内步骤卡片或注册到座舱控件上的叠加标注。研究计划进一步规定了一个三条件受控人因评估，比较视频加笔记基线、无状态基础的纯文本 LLM 以及基于状态证据的教学系统，评估指标包括完成率、程序性错误率、任务时间、NASA-TLX 工作负荷评分、前/后知识测验，以及在 2--4 周间隔后进行的保持和迁移测试。

当前实现交付了这一愿景的技术基础。第\ref{sec:intro-scope}节描述了已实现的系统范围，记录了设计如何从原始研究计划愿景中演进。受控人因评估在第\ref{ch:evaluation}章第\ref{sec:eval-planned}节中描述，构成本研究议程的下一阶段。

\section{当前实现范围}\label{sec:intro-scope}

当前实现是一个双平台教学运行时，由四个集成的子系统组成。

\paragraph{平台。}
系统同时支持桌面/DCS 和 VR（Quest~3）配置。在桌面端，显示器为标准显示器；输入通过键盘和 HOTAS（手不离杆操纵系统）；输出渲染为 DCS 屏幕上的座舱叠加高亮。VR 支持通过 VR\_MIRROR 和 VR\_allow\_MFD\_out\_of\_HMD 配置、导师文本 UDP 注入到 DCS 游戏内文本区域，以及复合面板截图兼容性验证来实现。VR 配置的人因验证不在本论文当前范围之内，将在计划的研究设计中处理（第\ref{ch:evaluation}章，第\ref{sec:eval-planned}节）。

\paragraph{遥测数据基础。}
遥测子系统通过带源丢失跟踪的变量解析、增量去噪处理（阈值、防抖动和逐变量过滤）以及用于提示安全压缩的增量聚合，处理原始 DCS-BIOS UDP 接收。这些阶段解决了处理嘈杂、高频仿真器遥测数据的实际需求。

\paragraph{VLM 视觉事实提取。}
系统包含一个视觉事实提取流水线，以弥补 DCS-BIOS 遥测留下的缺口：若干关键程序步骤（S08、S15、S18）需要对未通过 DCS-BIOS 导出的显示页面内容进行视觉确认。该组件涵盖结构化视觉事实本体设计、带人工审查的数据集构建、双语 LoRA 微调，以及跨两个模型骨干的自动化基准测试评估。

\paragraph{程序包和基础设施。}
程序定义、门控规则、遥测映射、错误分类法和视觉事实本体被组织为声明式 YAML 配置（\emph{程序包}），而非将其隐式编码在提示或代码中。系统还包含事件日志记录与回放基础设施、自动化评分引擎，以及在没有模型可用或模型输出验证失败时运行的确定性降级路径。

\section{贡献}\label{sec:intro-contributions}

本论文做出以下五项贡献，按创新性排序：

\begin{enumerate}

\item \textbf{面向基于 VLM 的座舱状态提取的结构化视觉事实本体设计及抽象层次设计原则。}
将复合视觉目标分解为原子性、可局部验证的命题，使 Run-002 留出集上的关键假阳性从 13 降至 4（减少 64\%），使 Run-004 留出集上的关键假阳性从 70 降至 8（减少 89\%）。本论文将这一经验结果提炼为可迁移的设计原则：应让 VLM 提取可观察的视觉原子，程序性解释应归属于下游推理。此贡献在第\ref{ch:system-design}和第\ref{ch:methodology}章中描述，并在第\ref{ch:evaluation}章第\ref{sec:eval-tech}节中进行评估。
% 证据：C-VLM-01, C-VLM-02, C-VLM-03, C-VLM-04, C-VLM-05

\item \textbf{一个完整、可复现的小数据 VLM 领域适配流水线。}
该流水线涵盖 DCS 截图捕获、AI 预标注、Label Studio 人工审查、双语 SFT 导出、LoRA 微调，以及在经核实训练数据零重叠的独立留出集上进行自动化基础模型与 LoRA 对比基准测试。以 180--220 个人工审查样本进行了验证，产生了 928 条双语训练数据；从原始截图到基准测试指标的所有工件均被存储，可供独立检查和复现。此贡献在第\ref{ch:system-design}和第\ref{ch:methodology}章中描述。
% 证据：C-VLM-03a, C-VLM-07, C-DATA-01, C-TRAIN-01

\item \textbf{一个集成遥测-视觉-知识的教学架构，具备可验证的证据溯源能力。}
每个叠加目标和步骤推荐都携带可追溯的证据引用——遥测变量、门控规则评估、检索到的 RAG 片段或视觉事实观察——在模式层面通过运行时生成的 JSON Schema \texttt{if/then} 规则强制执行，而非仅仅记录以备事后审计。该架构遵循端口-适配器模式，并包含确定性降级路径。此贡献在第\ref{ch:system-design}、\ref{ch:methodology}和\ref{ch:implementation}章中描述。
% 证据：C-ARCH-01, C-ARCH-02, C-ARCH-03, C-PROC-01, C-PROC-02, C-TELEM-01, C-RAG-01, C-RUNTIME-01

\item \textbf{跨骨干泛化证据。}
相同的双语 SFT 方案（928 条）从 Qwen3.5-9B 迁移到 Gemma-4-31B，均取得一致改进，证实了数据方案和本体设计并非针对特定架构。Gemma LoRA 适配器在 Run-002 上实现零关键假阳性，并表现出质上不同的错误特征（保守型与激进型），表明该流水线能够刻画骨干特定的行为特征，这对安全关键型部署决策具有参考价值。此贡献在第\ref{ch:evaluation}章第\ref{sec:eval-gemma}节中呈现。
% 证据：C-VLM-06, C-VLM-03b

\item \textbf{一个可扩展的运行时与评估基础设施。}
程序包驱动、仿真器无关的架构包括程序状态机、门控规则引擎、确定性降级路径、JSONL 事件日志记录、回放验证、自动化评分，以及一个面向基于 VR 的人因评估的设计层面框架——全部通过自动化测试实现。计划中的人因评估设计（一项三条件受试者间研究，比较视频加笔记、无状态基础纯文本 LLM 和基于状态证据教学三种条件）在第\ref{ch:evaluation}章第\ref{sec:eval-planned}节中记录，构成本研究计划的下一阶段。此贡献在第\ref{ch:system-design}和第\ref{ch:evaluation}章中描述。
% 证据：C-ARCH-01, C-PROC-01, C-RUNTIME-01, C-HUMAN-01, C-HUMAN-02, C-HUMAN-03, C-DATA-COLLECT-01
\end{enumerate}

贡献 1--4 由代码仓库中已验证的声明和基准测试工件支撑。贡献~5 结合了已实现的基础设施（自动化测试、回放、评分、双平台支持）与文档化的评估设计，其实施超出了本论文的范围。

\section{论文结构}\label{sec:intro-structure}

论文的剩余部分组织如下。

\textbf{第\ref{ch:background}}章提供理解本系统所需的领域和技术背景。它详细描述了 F/A-18C 冷启动程序，介绍了视觉事实本体及其从 8-fact v1 到 13-fact v2 的演进，并综述了智能教学系统、基于仿真器的培训、基于规则和状态感知的教学、面向结构化输出的 VLM 适配以及 AR/VR 环境中可解释 AI 辅助等相关工作。

\textbf{第\ref{ch:system-design}}章介绍所提出系统的设计。它从问题陈述中推导设计目标，描述端口-适配器架构，追踪完整帮助循环中的运行时数据流，并详细阐述遥测处理流水线、程序和门控规则引擎、仿真器适配层、事件日志与回放基础设施以及 VLM 适配组件的设计。该章最后与原论文研究计划进行系统性比较，记录设计在实现过程中的演进。

\textbf{第\ref{ch:methodology}}章描述 VLM 适配流水线的方法论框架。涵盖数据集构建（Run-001 至 Run-005，本体版本，标注分布，经核实零重叠的留出集构建），截图-预标注-审查-导出-训练-基准测试流水线，Qwen3.5-9B 和 Gemma-4-31B 的 LoRA 微调配置，以及基准测试协议，包括指标定义和污染控制。

\textbf{第\ref{ch:implementation}}章记录技术栈、核心领域逻辑模块、遥测与 DCS 集成、结构化帮助生成、VLM 视觉事实提取、回放与日志基础设施以及 CLI 和运行时入口点的实现细节。

\textbf{第\ref{ch:evaluation}}章分为两部分。Part~A 报告当前技术结果：数据集和训练摘要、8-fact v1 基线、主要 13-fact v2 Qwen 基准测试结果、Gemma 骨干对比、逐事实错误分析，以及运行时基础设施就绪度评估。Part~B 描述计划中的人因评估：原始评估愿景、计划指标、所需基础设施升级、拟议实验设计，以及已知有效性威胁编目。Part~B 中的所有陈述均代表未来工作。

\textbf{第\ref{ch:discussion}}章对结果及其局限性进行解读。它考察了项目为何从 VR 优先转向遥测/VLM 重度实现，阐明当前基准测试能够和不能够证明的内容，分析本体从 8-fact 到 13-fact 的演进，论证人因证据为何仍然不可或缺，并识别将基准测试成功解读为学习成功的风险。

\textbf{第\ref{ch:conclusion}}章总结已完成的工作，重申贡献，并概述未来工作方向，包括 VR 运行时集成、人因评估、本体向其他程序的扩展、多帧时序推理以及在线适配。
