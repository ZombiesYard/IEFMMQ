\chapter{理论背景与相关工作}\label{ch:background}

引言将本论文框架定义为一个证据设计问题：基础模型应仅通过运行时系统能够观察、验证和回放的证据来解释当前训练状态。因此，本章并不泛泛综述 VR、飞行器模拟或基础模型，而是围绕一个问题审视最接近的研究线：为什么程序性 VR 模拟需要一个基于证据的教学循环？

答案是逐层累积的。手册和检查单提供权威性，但不提供实时状态。智能教学系统提供任务模型，但通常不是围绕多模态模拟器中的基础模型生成而构建。检索增强生成（RAG）为文本提供依据，但其本身并不知道座舱是否真的处于所声称的状态。AR/VR 引导将指令保持在任务上下文中，但其大部分内容是预编写或静态的。视觉语言模型（VLM）可以读取显示图像，但其输出必须先转化为有边界的视觉事实，才能影响教学系统。本论文的贡献正位于这些缺口的交汇处。

\section{沉浸式模拟中的程序性训练}\label{sec:bg-procedural}

程序性训练不同于事实性教学，因为成功取决于在状态约束下的有序操作。学习者不仅需要知道某个操作是什么，还需要知道何时允许执行、如何检查该操作是否已生效，以及当中途状态与预期不符时如何恢复。在航空和工业环境中，这些要求通常通过手册、检查单、教练和模拟器程序外化。飞行模拟具有悠久的训练传统，但模拟器的有效性取决于任务、反馈和教学设计，而不仅仅取决于逼真度~\citep{hays1992flight}。

本论文使用的冷启动任务是此类教学的一个合适压力测试。它足够紧凑，适合在硕士论文中研究，同时又对序列和状态敏感，并且依赖视觉媒介。在 DCS World 中，学习者通过 Meta Quest~3 头盔操作 F/A-18C Lot~20。该任务要求完成供电、发动机启动、显示器使用、导航校准、飞行控制检查和最终滑行前配置~\citep{dcsworld,eagledynamics2023hornetguide}。纸质检查单可以描述这些步骤，但交互式教学系统必须知道当前哪个步骤可执行，以及哪些证据支持这一判断。

虚拟现实会放大低质量辅助的代价。佩戴头盔的学习者更难忍受切换到 PDF、搜索桌面窗口或回放外部视频。面向装配和维护的 AR 引导展示了将指令嵌入用户任务上下文的价值~\citep{tang2003arassembly,henderson2011ar,palmarini2018ar}。本论文采纳这种上下文化动机，但增加了一个更严格的系统条件：生成的帮助信息必须依据当前的模拟器状态，而不仅仅是视觉上放置在座舱附近。

\section{现有辅助方法}\label{sec:bg-existing}

\paragraph{手册、检查单与模拟器训练。}
本案例研究最权威的来源是 DCS World 模拟器、F/A-18C 手册/训练材料及其衍生的预编写程序包。这些来源定义了程序性先验知识。它们规定了哪些操作是重要的，以及应当发生哪些状态转移。其局限性在于它们不会自动观察学习者的当前状态。检查单中的某一行在抽象层面可能是正确的，但在当前时刻可能是错误的——如果某个前置条件尚未满足，或者学习者已经越过了所描述的状态。

\paragraph{智能教学与基于约束的教学。}
智能教学系统（ITS）研究长期将显式任务模型、学习者状态跟踪、反馈和基于约束的诊断视为有效教学的核心~\citep{vanlehn2011relative,kulik2016its,mitrovic2012constraint,aleven2009example}。这与本文原型直接相关：教学系统需要的不只是对话能力，还需要表示任务和学习者进展。区别在于运行环境。当前系统并非带有封闭问题接口的经典 ITS。它通过遥测、座舱显示图像、预编写门控条件和事件日志来观察高保真模拟器，同时将基础模型作为有边界的组件使用。

\paragraph{RAG 与有依据的语言模型辅助。}
RAG 使语言生成以检索到的文档为条件，而不是只依赖参数记忆~\citep{lewis2020rag}。在教育领域，大型语言模型可以生成灵活的解释和反馈，但也存在缺乏依据的自信、虚构引用以及流畅但脱离上下文的答案等风险~\citep{kasneci2023chatgpt,ji2023hallucination}。神经生成忠实性研究同样表明，流畅的生成文本可能偏离其源证据~\citep{maynez2020faithfulness}。SayCan 等有依据动作生成工作将语言合理性与动作可行性相分离~\citep{ahn2022saycan}。本文原型遵循同样的设计直觉：一个响应可能流畅且有来源依据，但只有当运行时系统能够验证状态、步骤、证据引用和叠加层目标时，才应将其作为程序性指导呈现。

\paragraph{AR/VR 引导与模拟器遥测。}
AR/VR 程序性引导解决了将帮助信息保持在任务上下文中的交互问题~\citep{palmarini2018ar}。模拟器遥测解决了一个不同的问题：观察状态。在本论文中，外部遥测接口只作为原始模拟器状态的输入通道；本文不把该接口本身作为实现贡献。贡献始于原始遥测数据进入教学运行时之后：系统选取相关变量，将原始控件映射到程序级谓词，区分源数据缺失与观察到的假值，将遥测与视觉事实和程序门控条件相结合，并记录结果证据以供回放。

\section{为何现有方法在此场景中不充分}\label{sec:bg-gap}

本案例研究同时需要四个特性。第一，辅助必须具有实时状态感知能力。一个仅检索正确手册段落的系统，如果模拟器状态尚未达到所需的前置条件，仍可能推荐错误操作。第二，辅助必须是多模态的。原始遥测数据覆盖了许多开关位置和指示器，但座舱显示页面和文本线索同样重要。左右数字显示指示器（DDI）和先进多用途彩色显示器（AMPCD）包含无法始终被简化为简单遥测字段的冷启动证据。

第三，辅助必须是可审计的。当自然语言回答可能指导学习者的下一步操作时，仅有一个回答是不够的。系统应保留为何该回答被接受、修复、降级或拒绝的原因。这驱动了后续章节中对事件日志和回放的重点关注。第四，辅助必须是有边界的。基础模型不应虚构步骤标识符、叠加层目标、来源引用或视觉观察。这些元素必须由程序包、来源策略、模式验证和约束检查来控制。

这四个需求解释了本论文的架构。手册和检索提供文本权威性。ITS 和基于约束的教学提供对显式任务状态的需求。遥测提供高置信度的模拟器变量。VLM 提供选定的视觉事实。运行时系统将它们绑定为一个证据包，之后才请求语言模型生成解释。

\section{基础模型作为有边界组件}\label{sec:bg-foundation}

基于 Transformer 的基础模型为现代语言和多模态系统提供了表征和指令遵循的基础~\citep{vaswani2017attention}。在本论文中，它们被有意地视为组件，而非整个教学系统。语言模型接收一个证据包并返回一个结构化响应。VLM 接收一张图像并返回一个结构化视觉事实对象。两种输出在被允许影响面向用户的指导之前都要经过检查。

这种组件视角改变了"解释"的角色。解释不仅是有帮助的文字，更是断言与证据之间的可检查关系。如果教学系统告知学习者应继续进行飞行控制检查，运行时系统应能够识别：哪个步骤处于活跃状态、哪些前置条件已满足、哪些检索到的源材料或程序规则支持该指导，以及相关视觉或遥测证据是否存在。如果证据缺失，模型不应被允许用自信叙述填补空白。

人机交互和可解释 AI 领域的工作为这种谨慎态度提供了依据。可解释 AI 研究强调理解系统为何产生某个推荐以及如何评估这类解释的需求~\citep{gunning2019xai,hoffman2018metrics}。人机交互与自动化研究强调可理解性、适度信任、不确定性处理和可恢复性~\citep{lee2004trust,amershi2019guidelines}。本文原型在一个狭窄的程序性场景中将这些理念操作化：响应模式、证据引用类型、来源策略、叠加层白名单和回放日志，正是使流畅的模型答案变得可检查的机制。

\section{视觉事实提取与 PEFT 适配}\label{sec:bg-vlm}

视觉语言模型将基础模型的能力扩展到图像-文本任务。Qwen-VL、Qwen3-VL、LLaVA 和 InstructBLIP 等通用 VLM 工作展示了视觉编码器和语言解码器如何支持图像推理、视觉问答、指令遵循和富含文本的感知~\citep{bai2023qwen,qwen3vl2025,liu2023llava,dai2023instructblip}。本论文只在窄范围内使用这些能力。VLM 不被要求进行自由形式的场景描述，而是返回一个基于固定视觉事实本体论的类型化 JSON 对象。

视觉事实表示有三种状态：\texttt{seen}（已见）、\texttt{not\_seen}（未见）和 \texttt{uncertain}（不确定）。一个事实如 \texttt{fcsmc\_final\_go\_result\_visible} 是一个关于可见显示线索的局部断言，而非关于整个 FCS BIT 步骤已完成的断言。这一区分至关重要。最初的 8 事实本体论包含较多复合目标，暴露出一个反复出现的失败模式：即使人工标签为 \texttt{not\_seen}，模型也可能将程序完成类事实报告为 \texttt{seen}。当前的 13 事实本体论将此类目标分解为局部视觉原子，由下游程序引擎加以解释。

这一设计与屏幕和 GUI 理解相关。屏幕内容模型和 UI 数据集强调固定区域、符号化文本和布局，而非普通自然图像~\citep{deka2017rico,wang2021screen2words}。座舱显示器具有同样的结构化特征。一个微小的视觉线索可能是一个按键标签、一个页面标题、BIT 结果表中的一行，或一条暂时的校准消息。因此，本体论充当了感知与控制逻辑之间的桥梁。

\subsection{结构化输出与可靠性指标}\label{sec:bg-metrics}

VLM 任务是在一个小型本体论上进行结构化预测。对于每张图像，模型预测一个分类状态向量而非说明文字。JSON 格式是集成接口，但学习问题不仅仅是 JSON 生成。模型必须将视觉证据与事实定义对齐，区分页面标签与实际页面，区分暂时性中间状态与最终状态，并判断某一线索何时过于模糊而无法做出 \texttt{seen} 或 \texttt{not\_seen} 的决策。

因此，评估使用多种指标。JSON 有效性和模式有效性衡量模型是否能参与运行时合约。事实准确率统计单个事实状态决策的正确率。宏平均 \(F_1\) 在不同事实间平衡状态类别。Seen \(F_1\) 聚焦于正向视觉检测。样本完全匹配询问整个视觉状态向量是否正确。关键假阳性统计高风险案例——模型对不应被视为可见的事实预测为 \texttt{seen}。最后一项指标至关重要，因为对完成类线索的一个假 \texttt{seen} 标签可能比一个仅仅触发额外检查的漏检更严重地污染下游程序推理。

\subsection{参数高效适配}\label{sec:bg-lora}

对于狭窄领域任务，对大型多模态模型进行全量微调通常是不必要或不切实际的。低秩适配（LoRA）冻结基座模型权重，为选定模块学习低秩更新矩阵~\citep{hu2021lora}。若基座权重矩阵 \(W\) 被冻结，LoRA 将更新表示为：

\[
  W' = W + \Delta W,\qquad \Delta W = BA,
\]

其中 \(A\) 和 \(B\) 为低秩可训练矩阵。PEFT、TRL 和 Unsloth 等参数高效微调库和工具使此工作流在本地实验中变得可行~\citep{mangrulkar2022peft,vonwerra2020trl,unsloth2024}。QLoRA 和 VeRA 等相关 PEFT 变体表明，该领域包含多种降低适配成本或参数量的方法~\citep{dettmers2023qlora,kopiczko2023vera}。本论文不提出新的 PEFT 算法，而是将 LoRA 作为领域特定的结构化视觉事实适配的实用机制。

因此，本文声明并非"一种更好的 LoRA 方法"，而是更窄的结论：对于 VR 程序性教学系统，结构化视觉事实配合小型领域 LoRA 适配，可以形成比直接使用基座 VLM 更可靠的证据通道。这使本体论设计、标签审查、验证集独立性和关键假阳性分析成为 ML 方法的一部分。第~\ref{ch:evaluation} 章中评估的 Qwen3.5、Qwen3.6 和 Gemma 线用于说明：模型选择是一个下游风险决策，而不只是排行榜决策。

本论文位于 ML 适配、教学系统、模拟器仪表化和 HCI/VR 评估的交汇处。其核心贡献并非发明手册、遥测、RAG、VLM、LoRA 或 AR/VR 引导，而是有纪律地集成这些要素：在高负载 VR 程序性训练场景中，只有当遥测、程序规则、检索、视觉事实、验证和回放日志共同约束模型可以说什么、做什么时，基础模型才能提供可审计的交互式解释。上文综述的任何单一研究线，都未能为当前案例同时提供全部需求：实时模拟器状态证据、多模态座舱事实、程序级权威、有边界的基础模型生成、面向头盔的引导，以及可回放的审计日志。
