\chapter{方法：基于证据的教学运行时系统}\label{ch:system-design}

本章在方法层面回答 RQ1。它描述本文原型如何将基础模型辅助转化为面向 F/A-18C Lot~20 冷启动任务的基于证据的帮助周期。运行时方法由对交互式解释至关重要的契约定义：程序建模、遥测依据、检索、视觉事实集成、响应验证、叠加层执行和回放。

\section{设计需求}\label{sec:design-goals}

运行时系统围绕六项需求进行设计。

\begin{enumerate}
\item \textbf{状态感知帮助。}教学系统必须依据当前模拟器状态进行推理，而非仅依据静态检查单。
\item \textbf{证据分离。}遥测、视觉事实、检索文本和程序规则在生成之后必须保持可区分。
\item \textbf{有边界的模型权限。}语言模型可以措辞解释，但不得静默定义程序状态或虚构叠加层目标。
\item \textbf{可检查的视觉感知。}VLM 应输出可检查和可评分的结构化事实，而非自由形式的座舱叙述。
\item \textbf{可回放性。}帮助决策必须可从记录的观察、证据包、模型输出、验证决策和叠加层动作中重构。
\item \textbf{先导实验就绪性。}运行时系统必须为后续分析生成参与者级工件，而不将形成性先导实验变成隐性的人工编码练习。
\end{enumerate}

这些需求直接源于论文标题。VR 中的交互式解释只有在解释可追溯至其所描述的模拟现实时才具有可辩护性。

\section{证据对象模型}\label{sec:design-evidence-model}

运行时系统将证据视为类型化对象，而非作为非结构化提示词文本。这是一个具有方法论后果的设计选择。遥测变量、失败的触发条件、检索句子、视觉事实和近期动作对教学系统都有用，但它们的含义不应相同。如果它们在生成前被压缩为一个段落，模型可以产生一个流畅但支撑不可重构的答案。如果它们作为类型化条目保留，运行时系统随后可以检查某个叠加层目标或诊断是否引用了实际存在的证据。

因此，证据对象模型为每个可用的上下文记录四个属性。第一，记录证据类型，如 \texttt{var}、\texttt{gate}、\texttt{rag}、\texttt{delta} 或 \texttt{visual}。第二，记录可在提示词、验证和日志中使用的稳定引用。第三，记录观测值或文本支撑。第四，在相关时记录可用性和质量元数据，如源数据缺失状态、帧时效或检索来源。这种结构使帮助响应具有可审计性，因为模型不能简单地引用任意理由，引用的理由必须对应当前证据包中的证据引用。

证据与解释之间的区分是有意为之的。一个视觉事实可以声明 \texttt{fcsmc\_final\_go\_result\_visible} 为 \texttt{seen}；它不应声明整个 FCS BIT 程序已完成。一个遥测变量可以声明襟翼开关处于 AUTO 位置；它不应决定学习者是否理解为何需要 AUTO。程序引擎和教学响应将证据组合为解释，但原始证据在该解释之下仍然可检查。

\section{程序包作为权威先验}\label{sec:design-procedure}

程序包是教学系统的预编写领域先验知识。它将 F/A-18C 冷启动表示为 33 个教学步骤，源自 DCS World 手册及本地训练材料。每个步骤都有稳定标识符、阶段、前置条件、完成门控条件、证据需求和 UI 目标。程序包以配置形式存储，而非嵌入提示词中。这使得程序保持可审计性，并将领域知识与模型措辞分离。

程序包在帮助周期中完成三项工作。第一，约束哪些步骤可被考虑为下一步。前置条件不满足的步骤不能被推荐为可用。第二，规定用于确认进展的证据。某些步骤以遥测为主导；依赖显示的步骤使用视觉事实绑定；当所需证据不可用时，其他检查会保守地降级。第三，定义叠加层目标空间。模型可以建议帮助信息，但运行时系统仅将视觉高亮映射到已知的座舱目标。

此设计避免了基于提示词的教学系统的常见失败模式。如果程序仅以自然语言表示，模型可以混合步骤、跳过前置条件或虚构目标名称。在本文原型中，提示词接收到运行时生成的证据包，但程序本身仍然是一个由系统控制的声明式对象。

\section{权威层级}\label{sec:design-authority}

运行时系统使用权威层级来决定什么可以覆盖什么。程序包对步骤顺序、允许的目标和证据需求具有权威性。遥测对直接导出的模拟器状态具有权威性。审查过的视觉事实仅对已定义的视觉命题具有权威性，且仅在其有效期和质量约束内。检索到的文本支持解释但不覆盖门控条件。LLM 措辞指导并可提出诊断，但不定义最终的程序状态。

这一层级防止了几种微妙的失败。若没有它，检索到的手册片段可能建议一个与当前活跃的机场冷启动包冲突的程序变体；VLM 可能因看到相关页面而推断步骤已完成，即便所需的遥测门控条件为假；LLM 可能选择一个不在当前 UI 白名单中的合理座舱控件。层级在面向用户的输出产生之前解决这些冲突：更严格的局部契约胜过来自更宽泛或更不可靠证据来源的冲突信息。

层级也支持优雅降级。如果视觉事实缺失，运行时系统不必放弃整个帮助周期。它仍可以使用遥测、门控条件、近期动作和检索到的程序文本。生成的响应简单地限制在那些证据来源能够支持的范围内。在实践中，这意味着教学系统可以说明视觉确认不可用，可以要求学习者核实某个显示，或给出仅有文字的提示而不高亮目标。用户看到不那么雄心勃勃的帮助，但不会被赋予虚构的确定性。

\section{遥测依据}\label{sec:design-telemetry}

外部遥测接口提供的原始模拟器遥测是模拟器状态的主要观察通道。运行时系统接收原始帧，归一化导出值，推导高层变量，并将缺失的源数据与假值分别跟踪。这一区分至关重要。变量可能为假是因为座舱状态未满足，也可能是因为源数据未导出或在当前帧中未被观察到。将两种情形同等处理会使教学系统过于自信。

遥测流水线还进行增量清洗和聚合。原始模拟器信号可能抖动、重复或变化过快而无法放入模型提示词。因此，运行时系统将高频状态变化转化为稳定变量和简明的近期动作摘要。这些摘要帮助教学系统解释发生了什么变化，同时避免将模型暴露给无界的日志。

遥测推导的证据示例包括：电池和发电机状态、APU 就绪状态、发动机转速阈值、油门动作、INS 模式、雷达模式、襟翼状态、停机刹车释放、IFEI BINGO 燃油设置，以及姿态来源选择。在遥测具有权威性的地方，不使用 VLM。这是一个有意的设计选择：当直接状态存在时，计算机视觉不应替代直接的模拟器状态。

\section{检索与来源策略}\label{sec:design-retrieval}

检索到的程序知识支撑帮助响应中的自然语言解释部分。运行时系统根据当前程序候选项和模拟器状态构建依据查询，检索本地手册或训练片段，并将其作为源材料提供给模型。来源策略限制允许哪些文档和块，这防止模型收到任意的仓库文本或不相关的模拟器材料。

因此，检索用于解释，而非不受控制的决策。程序包和遥测决定某个步骤是可用的还是被阻塞的；检索到的文本帮助措辞操作、检查和原理。这种分工反映了本论文更广泛的边界：基础模型应解释证据，而非取代证据。

\section{视觉事实集成}\label{sec:design-vision}

当显示内容无法从遥测可靠读取时，视觉事实进入帮助周期。运行时系统使用覆盖左 DDI、右 DDI 和 AMPCD 的固定复合面板布局。VLM 接收一帧或多帧候选图像，返回包含允许的事实标识符和状态的 JSON 对象。当前的 13 事实本体论包括页面可见性事实、FCS 页面标记、FCS-MC BIT 状态、HSI/地图图层事实，以及 INS 校准文本事实。

运行时系统将这些事实视为观察，而非程序决策。仅当程序包说明某个视觉事实相关时，它才能满足步骤绑定。某些事实是短效的，会迅速过期；其他事实——如最终 GO 提示——可能是粘性的，因为在学习者切换页面后，显示状态可能消失。粘性机制防止系统遗忘短暂但重要的视觉证据，同时保持证据的显式性。

这种架构正是 VLM 基准测试性能与运行时系统相关的原因。更高的事实准确率之所以重要，是因为下游规则引擎将这些事实用作证据。关键假阳性之所以重要，是因为它可以使完成类视觉线索在没有实际出现时显得存在。因此，运行时系统记录视觉事实调用并保存其输出，以供回放和错误分析。

\section{帮助周期}\label{sec:design-help-cycle}

帮助周期始于学习者请求辅助时——例如通过先导实验中使用的已配置热键路径。运行时系统随后执行以下序列：

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\textwidth]{figures/fig_help_cycle.pdf}
  \caption{实时基于证据的帮助周期。辅助始于观察快照，将其转化为证据包，请求模型给出结构化响应，验证结果，并记录显示的输出。}
  \label{fig:help-cycle}
  \Description[实时帮助周期图]{顺时针循环：从头盔帮助请求开始，到遥测和视觉快照、门控条件推理、证据包构造、基于来源的提示词生成、模型响应、约束验证、叠加层或回退输出，以及可回放事件日志。}
\end{figure}

\begin{enumerate}
\item 读取最新的遥测帧和推导变量。
\item 合并近期动作和任何可用的视觉事实观察。
\item 评估程序前置条件和完成门控条件。
\item 选择当前被阻塞、待处理或下一个候选步骤。
\item 在本地来源策略下检索源材料片段。
\item 构建包含证据包的结构化提示词。
\item 请求模型响应。
\item 按预期模式解析响应。
\item 验证叠加层目标和证据引用。
\item 执行、修复或抑制叠加层动作。
\item 在事件日志中记录观察、模型响应、验证结果和动作。
\end{enumerate}

因此，模型仅在证据组装后被调用。响应仅在验证后才被使用。这种排序是"解释现实"的运行时表达：模型解释一个有边界的证据包，系统检查该解释是否可以安全显示。

\section{结构化响应与叠加层验证}\label{sec:design-validation}

教学响应是结构化的而非自由形式。它包含诊断、推荐动作、检查、解释和叠加层目标等字段。运行时系统解析响应，按模式验证，并通过白名单映射叠加层目标。若模型提出一个不受支持的目标、过于粗糙的目标，或缺乏证据的动作，运行时系统可以修复输出、回退到仅文本引导或抑制叠加层。

该验证层对安全性和评估都至关重要。它防止模型通过任意文本直接控制视觉高亮。它也创建了模型输出需要修复的频率记录。在后续报告的先导实验中，所有已执行的叠加层动作都通过了验证；回退事件主要是修复或映射事件，而非完全的仅确定性响应。该结果在系统层面支撑了 RQ1，同时也展示了模型在何处仍需要运行时修正。

\section{不确定性与降级模式}\label{sec:design-degradation}

运行时系统必须将不确定性作为正常操作状态来处理。在实时模拟器中，帮助请求可能在开关正在移动、显示页面正在切换、某个遥测变量不可用或 VLM 帧已过时时到达。将这些情况当作普通假值处理会使教学系统过于自信；将它们当作硬故障处理又会使系统对实时使用过于脆碎。因此，该方法定义了降级模式。

第一种模式是\emph{证据缺失}。所需来源不可用，或来源已知超出当前观察合约。运行时系统仍可提供一般性程序指导，但不应声称状态已被检查。第二种模式是\emph{证据冲突}。例如，视觉事实和遥测推导的候选步骤可能指向不同的解释，此时更严格的权威层级和约束规则决定响应被修复、降级还是挂起。第三种模式是\emph{输出无效}。模型响应未通过模式、目标或证据引用验证，因此运行时系统回退到确定性或仅文本响应。

这些模式之所以重要，是因为它们使不确定性在日志中可见，并在适当情况下在面向用户的语言中可见。一个不能区分"你没有做这个"与"我无法观察这个"的教学系统会误导学习者。本文设计将这些情况分开处理。这在 F/A-18C 冷启动中尤其重要，因为某些步骤结合了缓慢变化的模拟器状态、短暂显示文本和手动座舱导航。运行时系统只有知道自身证据不完整时，才能提供真正有用的帮助。

\section{VR 交互边界}\label{sec:design-vr-boundary}

Meta Quest~3 环境影响了运行时设计，尽管本论文主要不是一项 VR 界面研究。在桌面环境中，用户可以更轻松地在模拟器、手册、聊天窗口和日志之间切换。而在头盔中，这种切换成本要高得多。指导必须简短、在空间上有用，并与学习者当前的动作同步。同时，如果 VR 指导高亮了过多目标、使用了过期状态，或打断了一个已在进行该动作的学习者，它可能变得侵入性。

因此，运行时系统将叠加层指导视为一个受约束的输出通道，而非装饰性 UI。高亮目标必须来自程序包的 UI 映射；多目标引导有数量限制；叠加层计划需要证据引用。当模型提出的目标过于粗糙或不够有依据时，约束层可以修复它或抑制叠加层。响应的语言部分仍然可用，但空间引导被持有更严格的标准——因为它直接塑造学习者在座舱中的注意力。

这一边界也解释了为何先导实验日志很重要。一次成功的 VR 试验不仅是参与者到达最后一步，更是可事后检查的一系列帮助请求、VLM 调用、修复、高亮和状态转移。没有这些记录，很难区分教学系统的帮助是否有效——是因为证据循环起作用，还是因为参与者已有经验，还是因为人类观察者非正式地填补了空白。导出的帮助周期工件使得这种区分在未来工作中可以被分析。

\section{日志、回放与导出}\label{sec:design-replay}

每个帮助周期和试验级事件都被写入可以回放和导出的日志。回放很重要，因为实时 VR 会话难以在当下检查。导出流水线生成试验摘要、每步骤编码文件、帮助周期表格、动作时间线、质量门控条件和会话元数据。这些工件同时支撑回归测试和先导实验分析。

回放设计也保护了对结果的解释。单独一个基准测试指标并不显示教学系统在实时试验中的行为；单独一个先导实验完成表并不显示叠加层路径是否有效。通过保存证据包、模型输出、验证决策和参与者级导出，本论文能够将 ML 可靠性与用户在 VR 中实际看到帮助的条件联系起来。

\section{方法边界}\label{sec:design-boundary}

运行时方法具有清晰的边界。它不是一个经过认证的飞行训练系统，不是一个通用的座舱自动化系统，也不是学习有效性的证明。它是一个研究原型，用于研究基于证据的基础模型解释如何在沉浸式模拟器内运作。后续章节评估该原型的两个最重要部分：VLM 视觉证据层和形成性 Quest~3 先导实验。
