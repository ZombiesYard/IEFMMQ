\chapter{方法：基于证据的教学运行时}\label{ch:system-design}

本章在方法层面回答 RQ1。它描述了 SimTutor 如何将基础模型辅助转化为面向
F/A-18C Lot~20 冷启动任务的基于证据的帮助循环。运行时方法由交互式解释所需的
契约定义：程序建模、遥测基础、检索、视觉事实集成、响应校验、覆盖层执行以及
回放。

\section{设计需求}\label{sec:design-goals}

该运行时围绕六个需求进行设计。

\begin{enumerate}
\item \textbf{状态感知的帮助。} 教学系统必须基于当前模拟器状态进行推理，
而非仅依赖静态检查单。
\item \textbf{证据分离。} 遥测数据、视觉事实、检索文本以及程序规则在生成后
必须保持可区分。
\item \textbf{受限的模型权限。} 语言模型可以表述解释，但不得静默地定义程序
状态或凭空编造覆盖层目标。
\item \textbf{可检查的视觉感知。} VLM 应输出可检查、可评分的结构化事实，
而非自由形式的座舱叙述。
\item \textbf{可回放性。} 一条帮助决策必须能够从记录的观测、证据包、模型
输出、校验决策以及覆盖层动作中重建。
\item \textbf{面向被试的准备。} 运行时必须生成被试级别的产物以供后续分析，
同时不得将形成性被试变为隐藏的手动编码练习。
\end{enumerate}

这些需求直接源于论文标题。当且仅当解释可以追溯到其所描述的模拟现实时，
VR 中的交互式解释才具有可辩护性。

\section{证据对象模型}\label{sec:design-evidence-model}

运行时将证据视为带类型的对象，而非非结构化的提示文本。这是一个具有方法
论意义的设计选择。一个遥测变量、一个失败的门、一条检索到的句子、一个视觉
事实以及一个近期动作对教学系统都有用，但它们不应具有相同的含义。如果在
生成之前将它们折叠成一个段落，模型可以产出一个流利的回答，但其依据却无法
重建。如果将它们保持为带类型的条目，运行时随后可以检查覆盖层或诊断是否
引用了实际存在的证据。

因此，证据对象模型为每个可用的上下文片段记录四个属性。第一，记录证据类型，
如 \texttt{var}、\texttt{gate}、\texttt{rag}、\texttt{delta} 或
\texttt{visual}。第二，记录一个可在提示、校验和日志中使用的稳定引用。
第三，记录观测到的值或文本依据。第四，在相关情况下记录可用性和质量元数据，
如数据源缺失状态、帧年龄或检索来源。这种结构使得帮助响应具有可审计性，
因为模型不能简单地引用任意理由；所引用的理由必须对应于当前证据包中的
某个证据引用。

证据与解释之间的区分是有意为之的。一个视觉事实可以声明
\texttt{fcsmc\_final\_go\_}\allowbreak\texttt{result\_visible} 为 \texttt{seen}；它不应
声明整个 FCS BIT 程序已完成。一个遥测变量可以声明襟翼开关在 AUTO 位置；
它不应判定学员是否理解为什么需要 AUTO。程序引擎和教学响应将证据组合成
解释，但这些解释之下的原始证据仍然保持可检查。

\section{程序包作为权威先验}\label{sec:design-procedure}

程序包是教学系统的已编写领域先验。它将 F/A-18C 冷启动表示为 33 个教学
步骤，这些步骤源自 DCS World 手册和本地训练材料。每个步骤具有稳定标识符、
阶段、前置条件、完成门、证据需求以及 UI 目标。程序包以配置形式存储，而非
嵌入提示中。这保持了程序的可审计性，并将领域知识与模型措辞分离。

程序包在帮助循环期间完成三件事。第一，它约束哪些步骤可能被考虑为下一步。
当前置条件未满足时，一个步骤不能被推荐为可用的。第二，它指定用于确认进展的
证据。某些步骤以遥测为主；依赖显示屏的步骤使用视觉事实绑定；其他检查在
所需证据不可用时保守地降级。第三，它定义覆盖层目标空间。模型可以建议帮助，
但运行时仅将视觉高亮映射到已知的座舱目标。

这种设计避免了提示驱动教学系统的常见失败模式。如果程序仅以自然语言表示，
模型可以混合步骤、跳过前置条件或编造目标名称。在 SimTutor 中，提示接收
运行时生成的证据包，但程序本身仍然是一个由系统控制的声明式对象。

\section{权限层级}\label{sec:design-authority}

运行时使用权限层级来决定什么可以覆盖什么。程序包在步骤顺序、允许的目标
和证据需求方面具有权限。遥测在直接导出的模拟器状态方面具有权限。经过审查
的视觉事实仅对所定义的视觉命题具有权限，并且仅在其过期时间和质量约束范围
内。检索到的文本支持解释，但不覆盖门。LLM 表述指导并可以提出诊断，但不
定义最终的程序状态。

该层级防止了若干细微的失败。没有它，一条检索到的手册片段可能建议一种与
当前机场冷启动程序包冲突的程序变体。VLM 可能因为看到一个相关页面而推断
步骤已完成，即使所需的遥测门为假。LLM 可能选择一个不在当前 UI 白名单中的
貌似合理的座舱控件。该层级在面向用户的输出产生之前解决这些冲突：更严格的
局部契约胜过更宽泛或不太可靠的证据来源。

该层级还支持优雅降级。如果某个视觉事实缺失，运行时不必须放弃整个帮助循环。
它仍然可以使用遥测、门、近期动作和检索到的程序文本。生成的响应仅被限制在
这些证据来源所能支持的范围内。在实践中，这意味着教学系统可以说视觉确认不
可用，可以要求学员验证一个显示屏，或者在不高亮目标的情况下给出纯文本提示。
用户看到的是不够全面的帮助，但不是凭空编造的确定性。

\section{遥测基础}\label{sec:design-telemetry}

DCS-BIOS 遥测是模拟器状态的主要观测通道。运行时接收原始帧，归一化导出值，
推导高层变量，并将缺失的数据源与假值分开追踪。这种区分很重要。一个变量
可以为假，因为座舱状态未满足；也可以因为数据源未被导出或在当前帧中未被
观测到而不可用。将两种情况视为相同会使教学系统过于自信。

遥测管线还执行增量清洗和聚合。原始模拟器信号可能抖动、重复或变化过快，
不适合模型提示。因此，运行时将高频状态变化转化为稳定变量和简洁的近期动作
摘要。这些摘要帮助教学系统解释发生了什么变化，同时不将模型暴露于无界的
日志中。

遥测派生的证据示例包括：电池和发电机状态、APU 就绪、发动机 RPM 阈值、
油门运动、INS 模式、雷达模式、襟翼状态、驻车制动释放、IFEI BINGO 燃油
设置以及姿态源选择。在遥测具有权威性的地方，不使用 VLM。这是一个有意为之
的设计选择：当存在直接的模拟器状态时，计算机视觉不应替代它。

\section{检索与数据源策略}\label{sec:design-retrieval}

检索到的程序知识支持帮助响应中的自然语言解释部分。运行时从当前程序候选
和模拟器状态构建锚定查询，检索本地手册或训练片段，并将其作为源材料提供给
模型。数据源策略限制哪些文档和块是允许的。这防止模型接收到任意的仓库文本
或无关的模拟器材料。

因此，检索用于解释，而非不受控制的决策。程序包和遥测决定一个步骤是否可用
或阻塞；检索到的文本帮助表述动作、检查和理由。这种划分反映了论文更广泛的
边界：基础模型应该解释证据，而非替代证据。

\section{视觉事实集成}\label{sec:design-vision}

当显示内容无法从遥测中可靠读取时，视觉事实进入帮助循环。运行时使用固定的
复合面板布局，覆盖左 DDI、右 DDI 和 AMPCD。VLM 接收一帧或多帧候选图像
并返回一个 JSON 对象，其中包含允许的事实标识符和状态。当前的 13 事实本体
包括页面可见性事实、FCS 页面标记、FCS-MC BIT 状态、HSI/地图图层事实以及
INS 对准文本事实。

运行时将这些事实视为观测，而非程序决策。只有当程序包说明一个视觉事实是
相关的，它才能满足步骤绑定。某些事实存活时间短，很快过期；其他事实，如
最终 GO 提示，可能粘性更久，因为当学员更换页面后显示状态可能消失。粘性
机制防止系统遗忘短暂但重要的视觉证据，同时仍保持证据显式化。

这一架构使得 VLM benchmark 性能与运行时相关。更高的准确率之所以重要，是
因为下游规则引擎使用这些事实作为证据。关键的假阳性之所以重要，是因为它
可以使一个类似完成的视觉提示在不存在时看起来存在。因此，运行时记录视觉
事实调用并保存其输出，用于回放和错误分析。

\section{帮助循环}\label{sec:design-help-cycle}

帮助循环在学员请求帮助时开始，例如通过被试中使用的已配置热键路径。运行时
随后执行以下序列：

\begin{enumerate}
\item 读取最新遥测帧和推导变量。
\item 合并近期动作和任何可用的视觉事实观测。
\item 评估程序前置条件和完成门。
\item 选择当前阻塞、待处理或下一个候选步骤。
\item 在本地数据源策略下检索源片段。
\item 构建包含证据包的结构化提示。
\item 请求模型响应。
\item 根据预期 Schema 解析响应。
\item 校验覆盖层目标和证据引用。
\item 执行、修复或抑制覆盖层动作。
\item 将观测、模型响应、校验结果和动作记录到事件日志中。
\end{enumerate}

因此，模型仅在证据组装之后被调用。响应仅在校验之后被使用。这种顺序是
"解释现实"的运行时表达：模型解释一个有界的证据包，而系统检查该解释是否
可以安全显示。

\section{结构化响应与覆盖层校验}\label{sec:design-validation}

教学响应是结构化的，而非自由形式的。它包含诊断、推荐动作、检查、解释和
覆盖层目标等字段。运行时解析响应，根据 Schema 校验，并通过白名单映射
覆盖层目标。如果模型提出不支持的目标、粗糙的目标或缺乏证据的动作，运行
时可以修复输出、回退到纯文本指导或抑制覆盖层。

这一校验层对安全性和评估都很重要。它防止模型通过任意文本直接控制视觉高亮。
它还创建了模型输出需要修复的频率记录。在后面报告的被试中，所有执行的覆盖
层动作均通过了校验；回退事件主要是修复或映射事件，而非完全的仅确定性
响应。该结果在系统层面支持 RQ1，同时也显示了模型仍然需要运行时纠正的地方。

\section{不确定性与降级模式}\label{sec:design-degradation}

运行时必须将不确定性作为一种正常运行状态来处理。在实时模拟器中，帮助请求
可能在开关正在移动时、显示屏页面正在切换时、DCS-BIOS 变量不可用时或 VLM
帧过时时到达。将这些情况视为普通的假值会使教学系统过于自信。将它们视为
硬失败会使系统在实时使用中过于脆弱。因此，该方法定义了降级模式。

第一种模式是\emph{证据缺失}。所需的数据源不可用，或已知数据源超出当前
观测契约。运行时可能仍然提供一般性程序指导，但不应声称状态已被检查。第二
种模式是\emph{证据冲突}。例如，一个视觉事实和一个遥测派生的步骤候选可能
指向不同的解释。在这种情况下，更严格的权限层级和校验器规则决定响应是被
修复、降级还是暂缓。第三种模式是\emph{输出无效}。模型响应未通过 Schema、
目标或证据引用校验，因此运行时回退到确定性或纯文本响应。

这些模式之所以重要，是因为它们使不确定性在日志中以及在适当的用户可见对话
中可见。一个无法区分"你没有这样做"和"我无法观察到这个"的教学系统会误导
学员。SimTutor 的设计保持这些情况分离。这在 F/A-18C 冷启动中尤其重要，
因为某些步骤结合了缓慢变化的模拟器状态、短暂的显示文本以及手动座舱导航。
只有当运行时知道自己证据不完整时，它才能提供帮助。

\section{VR 交互边界}\label{sec:design-vr-boundary}

Meta Quest~3 环境影响了运行时设计，尽管本论文主要不是一项 VR 界面研究。
在桌面环境中，用户可以更容易地在模拟器、手册、聊天窗口和日志之间切换。在
头显中，这种切换成本要高得多。指导必须简短、在空间上有用，并与学员当前
动作的时间同步。同时，如果 VR 指导高亮过多目标、使用过时状态或打断已经
在完成动作的学员，它可能变得具有侵入性。

因此，运行时将覆盖层指导视为一个受约束的输出通道，而非装饰性 UI。高亮的
目标必须来自程序包的 UI 映射。多目标指导是有限的。覆盖层计划需要证据引用。
当模型提出过于粗糙或不够扎实的目标时，校验器可以修复它或抑制覆盖层。响应
的语言部分仍然可用，但空间指导受到更严格的标准约束，因为它直接塑造学员在
座舱中的注意力。

这一边界也解释了为何被试日志很重要。一次成功的 VR 试验不仅是被试到达最后
一步。它还是一系列可在事后检查的帮助请求、VLM 调用、修复、高亮和状态转换。
没有这些记录，很难判断教学系统有帮助是因为其证据循环起作用，是因为被试已经
有经验，还是因为人类观察者非正式地填补了空白。导出的帮助循环产物使这种
区分在未来的工作中可以分析。

\section{日志记录、回放与导出}\label{sec:design-replay}

每个帮助循环和试验级别的事件都被写入可回放和导出的日志。回放之所以重要，
是因为实时 VR 会话难以在当下检查。导出管线产生试验摘要、逐步骤编码文件、
帮助循环表、动作时间线、质量门以及会话元数据。这些产物同时支持回归测试
和被试分析。

回放设计也保护了对结果的解释。一个 benchmark 指标本身不能展示教学系统在
实时试验中的行为。一个被试完成表本身不能展示覆盖层路径是否有效。通过保存
证据包、模型输出、校验决策和被试级别的导出，论文可以将 ML 可靠性与用户在
VR 中看到帮助的实际条件联系起来。

\section{方法边界}\label{sec:design-boundary}

运行时方法有一个明确的边界。它不是一个经过认证的飞行训练系统，不是一个
通用的座舱自动化系统，也不是学习效果的证明。它是一个研究原型，用于研究
基于证据的基础模型解释如何在沉浸式模拟器内部运行。后续章节评估该原型的
两个最重要部分：VLM 视觉证据层和形成性 Quest~3 被试。
