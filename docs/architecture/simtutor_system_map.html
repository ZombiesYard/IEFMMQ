1. System Overview

SimTutor sits between the DCS F/A-18C simulator (rendered through a Quest 3 HMD) and a remote model server. DCS-BIOS exports real-time cockpit telemetry. The Vision Sidecar captures composite-panel screenshots. On each X1 help request, the Live Help Loop assembles evidence, calls the text LLM, optionally calls the VLM for visual-priority steps, and sends overlay highlights + Chinese text guidance back to the cockpit.

2. Live Help Cycle

3. VLM / LLM Separation

Critical architectural decision: The VLM is only a structured visual fact extractor. It never generates teaching text, overlays, or step decisions. The main help LLM is text-only (adapters/openai_compat_model.py). VLM is only called for visual-priority steps (S08, S15, S18, S19) where DDI page state must be confirmed. For all other steps the VLM is skipped entirely — the system checks requires_visual_confirmation from the pack.

4. Harness Engineering Objects

The harness is the safety layer between the LLM's raw output and the public cockpit response. It verifies that the chosen step is a valid candidate, repairs missing or invalid overlay targets, detects evidence contradictions, and can force text-only fallback when the model's proposal is unsafe. All harness objects live in core/ — they are pure domain logic with no I/O.

5. Experiment Export and Analysis Pipeline

After each trial, the raw JSONL event log is frozen into study-ready CSV artifacts. These are then aggregated across participants for thesis analysis. The pipeline is implemented across core/experiment_export.py and the CLI commands experiment-export / experiment-analyze in simtutor/__main__.py.
